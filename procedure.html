Procedure and trust policy

A result is verified here when it is on the main branch and the whole library passes the gate in scripts/check.sh: no placeholder or trust escape in the sources, every library file imported by the root file, a build with no warning, and an axiom check that allows only the three standard axioms of Lean and Mathlib. Trust comes from the Lean kernel; nothing else on this page asks to be believed.

What verified means

A theorem on the main branch has been checked by the Lean kernel against its statement, and every constant of the library depends on no axiom beyond propext, Classical.choice and Quot.sound. That says the proof is correct. It does not say that the statement is the right one: whether a Lean statement captures the intended causal claim is a matter of reading its hypotheses and its conclusion, which is why every statement is shown on the Reference page and the Methods page explains how statements are written.

The gate

The gate script on the main branch runs these steps, in this order: 1. source scan; 2. root imports every library file; 3. lake build without project warnings; 4. axiom check. Each prints PASS or FAIL, and the script fails if any step fails.

  1. Source scan.Every file under CausalInference/, the root file and lakefile.toml are scanned after comments, docstrings, strings and character literals are blanked out. Any of these identifiers is rejected: sorry, admit, axiom, unsafe, native_decide, implemented_by, extern, ofReduceBool, skipKernelTC. A set_option that turns a linter off is rejected as well, and the lakefile may turn off only the header linter (the file headers carry this project's license).
  2. Root imports.Every file under CausalInference/ must be imported directly by CausalInference.lean, so nothing escapes the build and the axiom check.
  3. Build with no warning.lake build must succeed, and its output must contain no warning from a file of this project, which keeps the linters of Mathlib's standard set clean.
  4. Axiom check.lake env lean scripts/AxiomCheck.lean walks every constant whose module lies under CausalInference, private ones included, computes the axioms it depends on with the mechanism behind #print axioms, and fails listing every constant that depends on an axiom outside propext, Classical.choice, Quot.sound. It is skipped, and counted as failed, when the build fails, so it never reads stale compiled files.

For commit 7f2b9d0 the site generator runs the scanner of step 1, read from scripts/check.sh at the same commit, over 97 files and finds 0 hits. Steps 3 and 4 need a Lean installation and are not run by the site generator.

Continuous integration

The main branch contains a continuous integration workflow (.github/workflows/ci.yml), which installs the pinned toolchain, fetches the prebuilt Mathlib files and runs scripts/check.sh.

Trust policy

A reader should need to trust only the Lean kernel, Mathlib, and the statements themselves.

No escape hatches

No sorry, no admit, no added axiom, no native_decide, and no unsafe, implemented_by or extern in the sources; the source scan enforces it on every commit, and the axiom check would catch any of them that slipped through.

Three axioms only

Every constant of the library depends on at most propext, Classical.choice, Quot.sound, checked for all of them at once by scripts/AxiomCheck.lean, not theorem by theorem.

Computation inside the kernel

Finite checks, such as the acyclicity or the districts of an explicit graph, are closed by decide on decision procedures proved correct in the library; the kernel evaluates them, and no compiled code is trusted.

Pinned environment

leanprover/lean4:v4.36.0 with Mathlib pinned to a fixed version. Continuous integration installs exactly these.

Untrusted sources

Published papers and books are read for their statements. Nothing is assumed because a source states it: every borrowed result is proved again in Lean, and departures from a source are stated in the module docstring.

Honest statements

Partial results carry their exact hypotheses in the statement. A theorem is never weakened silently to make a proof go through, and a statement never draws its content from a convention such as division by zero (see Methods).

The three standard axioms

Lean's kernel checks proofs in a small type theory. A handful of axioms are added by the core library, and Mathlib uses three of them throughout. A theorem that depends only on these is proved in ordinary classical mathematics.

propext
Propositional extensionality: two propositions that imply each other are equal. It lets a proof rewrite a statement by an equivalent one.
Classical.choice
The axiom of choice in type form: from a proof that a type is nonempty it produces an element of it. Together with the other two it implies the law of excluded middle, so proofs by contradiction and case splits on any proposition are allowed.
Quot.sound
Soundness of quotients: elements related by a relation become equal in the quotient type. Function extensionality (functions that agree everywhere are equal) is derived from it.

Forbidden constructs

sorry and admit
Placeholders that close any goal without a proof. They elaborate to the axiom sorryAx, which the axiom check rejects.
axiom
A declaration that asserts a statement without proof. Any added axiom could be false, and then everything would follow from it.
native_decide and ofReduceBool
Decide a computable proposition by compiling the decision procedure to native code and running it. The kernel then trusts the compiler and the runtime instead of checking the computation itself, and the proof depends on an extra axiom.
unsafe, implemented_by, extern
Ways to give a definition code that the kernel does not check, or to replace its compiled behavior with other code. They are excluded so that what is evaluated is exactly what is proved about.
debug.skipKernelTC
An option that skips the kernel's type check of declarations, which would remove the guarantee the whole policy rests on.

Reproduce the check

Install elan, the Lean version manager, then:

git clone https://github.com/adamrsophie/Causal-Inference-Lean.git
cd Causal-Inference-Lean
lake exe cache get
scripts/check.sh

lake exe cache get downloads the prebuilt Mathlib files for the pinned version, so that only this library is compiled. scripts/check.sh runs the four steps above, including the build, and ends with "All checks passed." or with the list of failed steps.
