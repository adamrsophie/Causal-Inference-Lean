Contribute

Contributions are welcome: a new theorem in an existing area, a counterexample that marks the boundary of a result, a module for an area on the roadmap, or a correction. Everything goes through the public repository on GitHub.

Repository: github.com/adamrsophie/Causal-Inference-Lean

Propose a result

  1. Open an issue.State the result in mathematical language, cite the published source where it appears, and say which area it belongs to. An issue first avoids duplicate work and settles the statement before the proof.
  2. Write the statement.Follow the Methods page: every modeling assumption is a named hypothesis, the setting (finite or measurable) is explicit, and no statement draws its content from a totalized value such as division by zero. Where it is meaningful, pair a positive result with a counterexample.
  3. Document the module.Each file opens with a module docstring that says what it proves, in which setting, and from which published sources, and notes any departure from them. Public declarations carry docstrings.
  4. Pass the gate.Run scripts/check.sh locally. It must end with "All checks passed.": no placeholder or trust escape, every file imported by CausalInference.lean, a build with no warning, and only propext, Classical.choice, Quot.sound as axioms. The procedure page explains each step.
  5. Open a pull request.Describe what the change proves, in plain language. Continuous integration runs the same gate on the pull request.

Where to start

The areas in progress and the planned areas of the roadmap, and the restricted settings listed on the Limits page, are natural places to extend the library: for instance, a result that is proved here only for a finite covariate or a binary treatment.
